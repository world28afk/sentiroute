Create `src/server/routes/dashboard/config.ts` with two route handlers:

**Route: GET /api/dashboard/config**
- Sets `Cache-Control: no-store` header on response
- Calls `opts.configManager.getSanitizedConfig()` and sends the result as JSON
- Response includes masked API keys (from getSanitizedConfig)

**Route: PUT /api/dashboard/config**
- Reads body as `Record<string, unknown>`
- Creates a merged config: `const merged = { ...opts.configManager.config, ...body } as Record<string, unknown>`
- Validates merged config with `configSchema.safeParse(merged)`
- On validation failure: returns 400 with `{ error: 'Config validation failed', issues: [...] }` where each issue has `{ path, message }`
- On validation success:
  - Replaces `opts.configManager.config = result.data`
  - Determines if restart is needed: `const needsRestart = body.model_slots !== undefined`
  - Writes to disk asynchronously (do NOT await — use `setImmediate` or fire-and-forget):
    ```typescript
    setImmediate(async () => {
      try { await opts.configManager.persistToDisk(); }
      catch (err) { fastify.log.error({ err }, 'Failed to write config'); }
    });
    ```
  - Returns `{ ok: true, restartRecommended: needsRestart, message: '...' }`
  - Message: "Config saved. Restart SentiRoute for structural changes to take effect." if needsRestart, "Runtime parameters updated." otherwise

**Type structure:**
```typescript
import type { FastifyPluginAsync } from 'fastify';
import type { ConfigManager } from '../../../config/manager.js';
import type { SentimentState } from '../../../sentiment/state.js';
import { configSchema } from '../../../config/schema.js';

type ConfigOpts = { configManager: ConfigManager; sentimentState: SentimentState };

const configRoutes: FastifyPluginAsync<ConfigOpts> = async (fastify, opts) => {
  // GET and PUT handlers here
};

Object.defineProperty(configRoutes, 'name', { value: 'dashboard-config' });
export { configRoutes };
```

**Critical implementation notes:**
- The PUT handler merges body with existing config BEFORE Zod validation — this lets the dashboard send partial updates. Full config must remain valid after merge.
- `body.model_slots !== undefined` triggers `restartRecommended: true` because structural changes (upstreams, model mappings) require restart. Runtime params (sentiment.*, server.*) do not.
- YAML write is fire-and-forget via `setImmediate` — do NOT `await` it in the response path. The user gets an immediate 200 response.
- Response header `Cache-Control: no-store` on GET — prevents browser caching config with API keys (even masked).
- Follow the existing FastifyPluginAsync pattern from `health.ts`: use `Object.defineProperty` for plugin name, export as `{ configRoutes }`.

### File 1: `src/server/routes/dashboard/state.ts`

**Route: GET /api/dashboard/state**

Returns current sentiment state for all model slots and the active threshold:

```typescript
// Response shape:
{
  threshold: number,          // from configManager.config.sentiment?.threshold ?? 0.6
  decayRate: number,          // from configManager.config.sentiment?.decayRate ?? 0.1
  cooldownMs: number,         // from configManager.config.sentiment?.cooldownMs ?? 300000
  antiFlapMs: number,         // from configManager.config.sentiment?.antiFlapMs ?? 60000
  now: number,                // Date.now() — lets UI calculate cooldown remaining
  slots: Record<string, {     // keyed by slotId
    slotId: string,
    score: number,
    currentUpstreamIndex: number,
    cooldownUntil: number | null,
    triggerCount: number,
    lastUpdated: number,
  }>
}
```

Implementation:
- Reads `const slots = opts.sentimentState.getAllSlots()`
- Reads sentiment config from `opts.configManager.config.sentiment` with defaults
- For each slot in `slots`, maps to response shape (include slotId, score, currentUpstreamIndex, cooldownUntil, triggerCount, lastUpdated — do NOT include switchHistory here, that's the history endpoint)
- Sets `Cache-Control: no-store` header
- Plugin name: `'dashboard-state'`

### File 2: `src/server/routes/dashboard/switch.ts`

**Route: GET /api/dashboard/history**

// Response shape:

- Sets `Cache-Control: no-store` header
- Plugin name: `'dashboard-switch'`

### File 3: `src/server/routes/dashboard/control.ts`

**Route: POST /api/dashboard/reset/:slotId**

Resets sentiment state for a given slot (clears score, history, cooldown, trigger count, sets upstream index to 0).

Implementation:
- Extracts `slotId` from `request.params` (Fastify colon-prefixed route param: `POST /api/dashboard/reset/:slotId`)
- Calls `await opts.sentimentState.resetSlot(slotId)`
- Returns `{ ok: true, slotId, message: 'Sentiment state reset for ' + slotId }`
- On unknown slotId: resetSlot creates a fresh default state, so this always succeeds — no 404 needed
- Sets `Cache-Control: no-store` header
- Plugin name: `'dashboard-control'`
