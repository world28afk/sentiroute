<objective>
Create the ConfigManager class, YAML write-back function, and API key masking utility. These three modules form the foundation that both the dashboard API routes and the app wiring depend on for runtime config mutation.

Purpose: Convert the current "load once, pass by value" config architecture to a shared mutable reference pattern. The ConfigManager wraps the Config object so that proxy routes, dashboard routes, and the main app all see the same in-memory state. Hot-updates to sentiment parameters take effect immediately. Structural changes persist to disk with a "restart recommended" notice.

Output: Three new files — `src/config/manager.ts`, `src/config/writer.ts`, `src/config/mask.ts`
</objective>


Implementation notes:

- Do NOT use lodash or any new dependency — pure TypeScript recursion
- The api_key field name matches the Zod schema's `api_key` property in `upstreamConfigSchema`
- This is a data transformation utility — no I/O, no side effects, pure function

```typescript
import type { Config, SentimentConfig, SentimentSignalWeights } from './schema.js';
import { writeConfig } from './writer.js';
import { maskApiKeys } from './mask.js';

export class ConfigManager {
  public config: Config;
  private configPath: string;

  constructor(initial: Config, configPath: string) {
    this.config = initial;
    this.configPath = configPath;
  }

  /** Hot-update sentiment parameters — immediate in-memory change, no file write */
  updateSentiment(params: Partial<SentimentConfig>): void { /* ... */ }

  /** Hot-update signal weights — immediate in-memory change, no file write */
  updateWeights(weights: Record<string, number>): void { /* ... */ }

  /** Write current config to YAML file (async, for structural changes) */
  async persistToDisk(): Promise<void> { /* ... */ }

  /** Return config with API keys masked for safe API responses */
  getSanitizedConfig(): Record<string, unknown> { /* ... */ }
}
```

Implementation details for each method:

**updateSentiment(params):**
- If `this.config.sentiment` is undefined, create it with defaults: `{ threshold: 0.6, decayRate: 0.1, cooldownMs: 300000, antiFlapMs: 60000 }`
- Merge `params` into `this.config.sentiment` using spread: `this.config.sentiment = { ...this.config.sentiment, ...params }`
- Use `as SentimentConfig` cast if TypeScript complains about the spread
- This is synchronous — takes effect immediately for all code that reads `configManager.config.sentiment`

**updateWeights(weights):**
- If `this.config.sentiment` is undefined, create it with defaults first
- If `this.config.sentiment.weights` is undefined, initialize as empty object
- Merge weights: `this.config.sentiment.weights = { ...this.config.sentiment.weights, ...weights }`
- This is synchronous — takes effect immediately

**persistToDisk():**
- Delegates to `writeConfig(this.configPath, this.config)`
- Returns the Promise from writeConfig
- Does NOT catch errors — let caller handle failures

**getSanitizedConfig():**
- Deep-clones `this.config` using `structuredClone()`
- Passes clone through `maskApiKeys()`
- Returns result cast as `Record<string, unknown>`
- The original `this.config` is NOT mutated (structuredClone ensures isolation)

Design notes:
- `config` is a public mutable property (not a getter) — this is intentional. Proxy routes read `configManager.config.model_slots` and see current state. When dashboard writes structural changes, `configManager.config = result.data` (from Zod validation) replaces the entire object.
- The class follows the same dependency-injection pattern as `SentimentState` — lightweight constructor, methods operate on owned state.
- No event emitters or observers needed — config reads happen per-request, so mutations are naturally visible.
